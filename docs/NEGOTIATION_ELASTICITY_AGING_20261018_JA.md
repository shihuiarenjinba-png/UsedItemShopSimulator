# 中古品店 — 供給元との交渉・価格弾力性・摩耗の仕様と受入試験
2026-10-18 / GitHub開発ブランチ `feature/elastic-demand-supply-haggle-aging-20261018`

## 遊びの設計
**ゆったり遊べる買い切りオフラインゲーム**を目指す。現実時間のタイマー・サーバー・アカウントは使わず、プレイヤーが1日進めるボタンを押すまで経営は進行しない。

### 仕入：店舗は需要側、持ち込み客は供給側
1. **希望額で購入**：売り手の希望額を払う。価格交渉は行わず成立確率100%。
2. **値引きを交渉**：提示額 `bid` と売り手の希望額 `ask` の比率が高いほど成立しやすい。成功率は画面に%表示。
3. **交渉失敗後**：初期設定は**購入しない**。プレイヤーが先に明示して選べば、希望額または希望額+約6%（100円単位切上げ）で購入できる。追加支出の事前同意なしには購入しない。
4. 売り手の成立判定は日付/品物/シードから決まり、同じ営業日の再計算で都合よく変化しない。
5. 所持金チェックは成立・失敗後のどちらの選択でも起こり得る**最大支払額**+家賃+修理費で行い、資金不足の強制購入を阻止する。
6. ゲーム内では仕入れ候補3点は各1点の離散的な供給。厳密な市場全体の供給曲線を推定しているのではなく、個々の売り手の受入確率を再現する**教育的・娯楽用の簡略モデル**。

交渉成功確率（ゲーム設定）：

```
r = 提示額 / 希望額
r >= 1                 : 100%
r < 0.60               : 1.5%
0.60 <= r < 1          : clamp(((r - 0.58) / 0.42)^2, 0.015, 0.97)
```

実際の売り手の取引確率を統計推定した値ではない。高額提示ほど基本的に成立しやすく、最低希望額での非交渉購入と選択肢を明確に区別する。

### 販売：店舗は供給側、来店客は需要側
各商品の販売価格はプレイヤーが自由に設定。商品種類により、価格変化への反応が異なる。

```
販売確率 ≈ clamp(基本購買確率 × 状態倍率 × 季節・評判倍率
                  × (店頭価格 / 現在の評価価値)^(-価格弾力性)
                  × 需要変動, 0.003, 0.94)

一日の予想販売数量 = Σ 在庫商品ごとの販売確率
実際の販売数量 = 商品ごとの独立した販売判定の合計（各0または1点）
```

商品種類ごとの弾力性（すべて**ゲーム上の調整値**）：

| 種類 | 弾力性 | 基本購買確率の設定 | 摩耗係数 |
| --- | ---: | ---: | ---: |
| 中古カメラ | 1.8 | 0.52 | 1.0 |
| ゲーム機 | 2.5 | 0.66 | 1.25 |
| オーディオ | 2.0 | 0.46 | 1.0 |
| 希少本 | 1.4 | 0.38 | 0.7 |
| 中古車 | 2.2 | 0.18 | 1.4 |

中古車は**21営業日目以降の一部持ち込み候補**として登場。初期店舗の資金繰りを妨げないよう後から解放する。実在する車種、車両状態、法的整備・安全検査を正確に再現しているものではない。

### 時間経過・摩耗・修理
- 各営業日の終わりに売れ残った在庫のみ `ageDays` が1増加し、現在の評価額は `1 - (0.002 × 商品摩耗係数)` 倍になる。
- 整備からの経過日数 `wearDays` が `ceil(30 / 摩耗係数)` 日に達すると、状態がA→B→Cの順に一段階悪化し、評価額をさらに0.94倍する。C以下には落ちない。
- 修理は既存の仕組みを利用し、現金を支払ってC→B、B→Aへ一段階改善。修理後は `wearDays=0` となるが、商品の保管日数は消えない。
- 店頭販売価格は**摩耗時も自動値下げしない**。値下げ・修理・待機はプレイヤーが選ぶ。
- 旧セーブで `ageDays` と `wearDays` が欠けている場合は0日として読み込み、同じセーブスキーマ1を維持。日数がゲームの経過日数を超える改ざんは拒否。
- 摩耗は業務ではなくゲーム内の設定。実物の商品価値や価格を推定する機能ではない。

### 金額の整合性
- 現金：前日の残高 − 買取費用 − 修理費 − 家賃 + 売上。
- 利益：売上 − 売れた商品の仕入原価（修理費の資産計上分を含む）− 家賃。
- 修理費と買取費は支払日には現金支出として反映し、**売れていない在庫の原価を同日に二重で損益計上しない**。
- 価格変更や交渉モード変更は予想だけ更新。実際の営業ボタンを押すまでセーブや経営は進まない。
