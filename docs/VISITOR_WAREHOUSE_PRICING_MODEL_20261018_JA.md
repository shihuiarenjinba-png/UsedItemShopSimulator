# 人の来店、買取交渉、修理倉庫と安全な値付けの設計
2026-10-18 / 対象: \`feature/visitor-workshop-economics-20261018\`

## 運営方針
- 現在の**3ステップ画面と自由な販売価格設定を維持**する。外部サーバー、アカウント、リアルタイム待機なし。プレイヤーが1日営業ボタンを押したときだけ日付が進む。
- 人物の描画は現段階では**人物タイプと絵文字、来店時刻、買ったか否か**。2Dキャラクターイラスト、動き、立体店内は未実装。「完成した人物表示」とは判定しない。
- 売り手は営業日あたり3件の持ち込み予定枠で、各持ち込みの時刻を日替わり乱数で決める。買い手は別にランダムに来店する。**売り手3件は現時点では固定であり、買い手人数のみ確率的**。
- 同じ日付・同じシードの来客と取引結果は再現する。セーブ再読込でくじの引き直しは起こらない。

## 1. 売り手との交渉：提示額に基づく供給応答
店舗は需要側であり、持ち込み客は供給側。交渉成功率は**実物の中古市場で測定した数字ではないゲーム上のパラメータ**。元の60%程度の提示額がほぼ成功しない急勾配を修正した。

\`\`\`
r = 買取提示額 / 売り手希望額
seller bias:
  急いで現金化したい +0.80
  通常の売り手       +0.12
  相場に詳しく慎重   -0.78

P(成立 | r, seller) = clamp(
  0.02 + 0.96 / (1 + exp(-(5.5 * (r - 0.56) + bias))),
  0.025, 0.975
)
通常価格での無交渉購入 r=1 は常に成立。交渉時もr>=1は成立。
\`\`\`

**例：希望25,000円に対し15,000円を提示。**
- 急いでいる: 約73%
- 通常: 約58%
- 慎重: 約37%

現金を守るため、交渉に失敗したときは**初期設定で購入しない**。プレイヤーがあらかじめ同意した場合のみ、希望額か約6%上乗せで購入する。現金チェックは成立・不成立・上乗せ時の最大支出を見て営業前に行う。

## 2. 買い手の人数・来店時間・商品の売れ方
買い手の来店人数はシード固定のポアソン分布から生成する（1日上限18人、ゲーム内期待値は約 \`2.8 + 評判/40 + 休日ボーナス1.1\`）。平均人数は評判でゆっくり変わる。平日と土日のリズムを模した7日周期の休日を設定。

- 営業時間は10時〜18時59分、来店時刻は分単位で変わる。
- 時間帯には重みを与え、昼頃と夕方の来客をやや多くする。**現実の店舗での実測データではなく、ゲーム上の分布。**
- 来客は「近所の常連」「ゲーム好き」「音楽好き」「本好き」「車を探す人」「通りがかり」から抽選し、興味のあるジャンルによって購入確率が変わる。
- 売場の商品それぞれに、種類別の**価格弾力性**・商品の状態・販売価格・日次需要変動・来客の嗜好を掛け合わせる。
- 各人物は最大1点、各商品も最大1回だけ売れる。売れるかどうかは決定的な乱数で判定。**在庫の総数だけで販売数量を増やさず、現実に来店した人数で上限がかかる。**
- 倉庫・修理台の商品は店頭販売に参加しない。来店0人または高額すぎる商品では販売0件が起こる。

## 3. 在庫工程：倉庫 → 修理台 → 倉庫 → 売場
購入した商品はその日に売場へ自動移動しない。
1. 持ち込み客から買取成立 → **倉庫（warehouse）**に保管。
2. 状態が悪ければ、修理費と設備を使って**修理台（workshop）**へ。修理に1営業日かかる。
3. 修理完了後 → **倉庫**へ移動。そこでプレイヤーが明示的に「売場に出す」を選択。
4. **売場（shelf）**の在庫だけを顧客が購入できる。売れなければ翌日へ持ち越す。
5. 売場8点、総在庫（倉庫・修理台を含む）18点。旧セーブで従来の売場に9〜18点存在する場合、超過分を**削除せずに倉庫へ自動移行**する。

修理の基本費は現在の評価額の約12%。購入済みの基本機材で同時に修理できるのは1点。設備強化には**65,000円を現金支出**し、修理台を2点に増設、単品修理費率を約9%へ低減する。設備の購入は投資支出として別途記録され、当日の会計利益と現金増減は異なる。高度な税務会計の減価償却・消費税計算は未実装。

## 4. 摩耗、原価、価格設定
既存の摩耗モデルを維持：日々の評価額低下と、商品ごとに数十日程度で一段階の状態悪化。修理済みは状態が改善し、再び販売するための時間と費用を伴う。

店側が入力する希望販売価格は自由。参考として21日間の保管を想定した価格を示す。

\`\`\`
調整原価 = 仕入原価(修理費の資産計上分を含む)
         + 想定保管中の価値目減り
         + 家賃3500円/日 × 想定日数/売場8枠
         + 設備強化時の1個当たり機材費回収目安（65000円/65個）

想定採算ライン = 100円単位で切り上げた調整原価
利益目標の参考 = 採算ライン × 1.18（切り上げ）

販売価格が採算ライン未満 → 警告
ただし売れる確率は別に計算し、採算ラインは利益保証ではない。
\`\`\`

価格が高いと価格弾力性により買い手の購買確率が下がる。プレイヤーは「売れやすさ」「利益率」「倉庫・売場の空き」「次の仕入れ予定」を総合して決める。

## 5. セーブと受入
旧セーブバージョン1を読み取れるようにした。新規フィールド \`equipmentLevel\` の欠落は基本機材1として扱い、\`zone\` の欠落は従来の売場品として扱う。売場上限を超える旧セーブだけ、商品をすべて残して倉庫へ移行する。壊れたセーブは自動上書きしない。

## 6. 次の品質改善
- 売り手人数そのものの変動、顔つきのあるオリジナル2Dキャラクターの作成、来客が移動するアニメーション。
- 過去に接客した常連の継続性、商品ごとの真贋・隠れた欠陥・修理部品の種類、機材の故障と維持費。
- 市場パラメータは第三者の現実データで推定された値ではない。ゲームとして複数方針の180日損益分布、平均来店数と失敗率を実測して調整する。
