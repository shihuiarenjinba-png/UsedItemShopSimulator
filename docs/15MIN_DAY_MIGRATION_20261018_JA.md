# 15分営業・セーブ互換・UI維持の実装記録（2026-10-18）

## 変更の範囲
- 1営業日の標準ペースを**現実時間15分**へ変更。ゲーム内時刻10:00～19:00は維持。
- 一時停止、営業再開、営業日途中の保存、閉店まで早送り、30営業日ごとの月末レポートと任意返済の仕組みを維持。
- **現在の3ステップのGUIや操作配置は変更していない**。元の魅力的な2D店内・人物画像はデザイン案であり、実ゲームの商用水準GUIとしてはまだコーディングされていない。
- 来店人数・販売抽選は実際に待った秒数で変わらない。早送りも同じ日・同じ経営方針・同じ乱数なら同一結果。
- セーブせずにアプリを閉じたり、画面非表示中は時計が進まない。再起動すると一時停止状態で再開。

## 重要：旧20分営業時計からの安全移行
旧時計の `elapsedMs` は20分＝1,200,000msを基準とした値。新時計は15分＝900,000ms。
保存時に `durationMs:900000` を追加。新フィールドがない場合だけ、旧20分形式と判定して**ゲーム内時間比率を維持して換算**。

```
新しい経過時間 = round(旧経過時間 * 900000 / 1200000)
```

例えば旧時計の14:30（50%）は新時計でも14:30（50%）にする。旧20分設定で14分経過した16:18は、新15分設定では10分30秒経過の16:18へ移る。時計変換は旧商用ソフトの存在を意味せず、開発ブランチに保存された途中データも破壊しないための互換処理。

- 時計の形式・経過時間・該当営業日を検証する。予期しない長さ/破損データを別の値で勝手に正常扱いしない。
- 確認できた時計だけ初回読み込み後に新形式で保存。セーブデータ本体が破損しているときは再保存せず保護。
- プレイ途中にリセットした場合、前回の時計と経営セーブを別枠で保持し、復元時に停止した時刻を取り戻す。

## 今回の独立試験
GitHubのJSコードを取得した隔離V8環境で**80件PASS**。特に以下を確認:
1. 15分で10:00→19:00、半分の経過で14:30。
2. 一時停止・アプリ終了中に時計が勝手に進まない。
3. 早送りでも同じ経営計算を行う。
4. 旧20分セーブが同じゲーム内時刻を保ち、読み込み時に新しい時計値へ正規化される。
5. 30/60日目の月次レポートとハード利息・任意返済が壊れない。
6. 買取、修理・倉庫、商品売却、旧セーブ保護、3モード開始とリセット復元の回帰。
7. 24種類のシード×30営業日で来客・販売ゼロ日・現金残高の限定バランステスト。

**これはNode CI/Windows上の実画面操作/15分の連続プレイ証拠の代替ではない**。Actionsの失敗、正式MSIX/WACK、継続試遊、商品素材権利は引き続きHOLD。

## まだゲーム完成ではない理由
- 画像案のような2D店内、人物・道具の絵、修理の汚れや音、0～100%の手動修理と途中販売が未完成。
- 来客イベントは閉店時にまとめて計算。15分間にリアルタイムでキャラクターが現れ、一人ずつ取引を確定するイベントエンジンは未実装。
- 180営業日の実際の遊びやすさ・価格弾力性・難易度ごとの完済率・エンディングのテストが必要。
- 既存UIの見た目を崩さず、本当に操作できるコンポーネントとして段階的に絵/効果を導入すること。
- Windows code担当が新規ローカル作業ディレクトリでNode試験、GUI、保存/復元、MSIX/WACKを行う。
