## 2. ゲーム開始時の3モード（推奨案・金額は最終バランステストまで仮決定）
ゲーム開始前にのみ出す**一度限りの導入画面**。「誰の資金で始めますか？」→ 説明 → 比較 → 確認 → 開業。
選択後は**モード選択 UI 自体を非表示**。モード名・残元金・金利・期日だけ資金画面で確認。セーブを消して新規開始する場合だけ改めて選べる。

| モード | 物語 | 開業借入金 | 利息 | 義務 | 判定 |
|--|--|--:|--:|--|--|
| EASY | 友達から借りる | ¥700,000 | 0% | 返済任意 | 無返済でも続行可／返すと称号や交流面の小さな報酬 |
| NORMAL | 母から借りる | ¥700,000 | 0% | 返済必須 | 180日までに元金全額返済する |
| HARD | 金融機関からの架空借入 | ¥700,000 | 元金残高の1.0% / 30営業日 | 元金・発生利息の返済必須 | 最終180日で未払いがあれば完済失敗 |

**開業時の貸借対照表（新規プレイ）**
- 現金（資産）= +700,000円
- 借入金（負債）= -700,000円
- 純資産 = 0円（厳密には *現金など資産の合計がゼロ* ではない）
- 初期基本工具を簿価0の貸与品として扱うか、開業費用から購入したものにするかを後続で整理。**プラスの簿価がある物品を0円純資産と二重計上しない。**
- 開業で設備・商品を購入したら現金から引き、棚卸商品・設備として資産側に記録。家賃などは費用として純資産に影響する。
- 既存の旧 v1 セーブへ**後付けで70万円の借金を追加しない**。旧セーブは明示した「旧ルール継続」でプレイ、またはバックアップを取って新規開始する。

元金70万円は現行ゲームの初期現金を踏襲して旧バランスとの比較を可能にするための暫定値。開業後の存続率・返済率を180日×複数シードで検証して変更する可能性がある。

## 3. 返済・利息の数式、資金 UI
硬いモードの利息は**営業日30日ごと**に締めて、毎回その時点の `未返済元金 × 0.01` を円単位で計上（小数点は最終計算で四捨五入）。未払い利息に追加の利息を掛けない。日割り実金利の再現ではなくゲームバランス用。

例：元金70万円を6回の30日区間で全く返済しなければ、利息 7,000円/区間、180日で合計42,000円（元金70万円とは別）。早く返すと後続区間の利息が小さくなる。NORMAL・EASYの利息は0。

返済操作はいつでもプレイヤーが実行する。**利息の滞納分→元金**の順に充当。債務は0未満にせず、返済額が手元現金を超えたら拒否、返済可能額の説明と今後の家賃/修理費のための資金警告を出す。返済操作と日次営業処理の二重徴収を防ぐ台帳を持つ。

返済画面の固定場所：トップの `💴 資金・返済` タブ＋上部残高からの詳細リンク。表示する内容:
- 手元現金、商品/設備資産の参考価額、借入元金残高、未払利息、差引純資産
- 次回の利息日/最終返済日、支払期限、返済の進捗
- 返済額入力、`今回は返さない` / `一部返済` / `全額返済` ボタン
- 売れるか分からない商品の評価価額を即時現金と同一視しない。最低3日分の家賃 (¥10,500) を予備費の**推奨**として警告するが、プレイヤーの裁量を残す。
- EASYでも友達に返すことが可能。NORMAL/HARDは最終日に完済できない場合、営業自体が消えるのではなく、**明示的な未達エンディング/成績評価**にする。

## 4. 修理進捗：完成イメージの固定表示をやめる
トップナビは `📦 倉庫 → 🔧 修理台 → 🏬 売場` + `💴 資金・返済`。倉庫は9品/ページ、10点目から「2ページ目」を表示。ページ分けと**実際の保管最大数は別**。当初容量は旧ルール18点を維持。

修理台：倉庫から商品を選ぶ → 選んだ商品を中央に大きく表示 → 周囲に**所有工具**（ドライバー、ピンセット、ブラシ、クリーナーなど） → 工具を選んで作業 → 進捗を加算。必要な道具/部品の費用と、操作による時間・改善内容を明示する。

道具は**交渉なしの定価購入**。個別購入と「必要工具をまとめて定価購入」ボタンを併設し、購入額の事前確認、現金不足判定、二重購入防止を行う。

修理進捗は0〜100%、現物の埃・錆・傷などを段階に合わせて弱める。**完成後の理想画像は出さない**。途中段階でも商品を売場に出せるが、「ジャンク/現状品/部分整備済み/整備済み」の正確な状態を表示し、価格・買い手への説明・評価に反映。進捗100%を販売条件にしない。道具使用に短いSEを付け、音のオン/オフ設定を保存する。静止画像であっても初回から操作が分かるよう設計する。

修理進捗を旧 `grade` A/B/C と混同しない。既存セーブは現在のグレード・修理位置を保持し、新しい作業進捗や工具台帳は移行時に整合する値を設定する。データ整合が確認できない場合は古いセーブを上書きしない。
